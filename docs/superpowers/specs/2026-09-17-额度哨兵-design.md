## 1. 总体架构

```text
GitHub Actions（每 30 分钟 cron）
  ├─ 轮询 codex-resets.com/api/resets
  ├─ 与仓库 data/events.json 做 diff
  └─ 有新的确认重置事件时：
       1. 调用企微群机器人 webhook（@所有人，附原推直链）
       2. git commit 数据文件 → 触发 Vercel 重新部署（约 1–2 分钟生效）

Vercel（Next.js App Router，ISR）
  ├─ 页面：构建时读 data/events.json，派生全部统计
  ├─ API route /api/state：客户端兜底刷新当前状态（可选）
  └─ RSS /feed.xml：构建时生成

人工兜底（信号源失效时）
  └─ 录入脚本 pnpm record --tweet <url> --type reset --title ... --at ...
       校验字段后写入 events.json，走同样的 commit → 部署 → 推送链路
```

要点：

- **Git 是唯一持久层**。无数据库、无 KV；数据变更 = 一次 commit，天然具备审计日志与回滚能力，与"每条记录可核验"的产品价值观一致。
- 页面上所有统计（累计次数、平均间隔、最长间隔、距上次天数、概率）一律由 `events.json` 派生计算，禁止手工维护数字，避免数据不一致。
- 新事件从"接口出现"到"页面生效"延迟约 2 分钟（含部署），推送（企微群）先于页面生效，时效排序符合用户价值优先级。

## 2. 数据结构

`data/events.json`（唯一数据源，schema 版本化）：

```json
{
  "version": 1,
  "events": [
    {
      "id": "2098685367058612394",
      "type": "reset",
      "title": "全量重置已传播完成",
      "summary": "Tibo 确认所有重置已经传播完成。",
      "announcedAt": "2026-09-12T08:09:17Z",
      "tweetUrl": "https://x.com/thsottiaux/status/2098685367058612394",
      "verified": true,
      "source": "codex-resets-poll"
    }
  ]
}
```

- `type` 枚举：`reset`（确认重置）/ `banked`（重置卡）/ `capacity`（容量信号）/ `normal`（普通动态）。
- `source` 枚举：`codex-resets-poll`（自动）/ `manual`（人工录入），页面不区分展示，仅用于内部审计。
- `id` 使用推文 ID，天然去重键。
- 冷启动：从 codex-resets.com 公开接口导入全部 53 条历史事件，`type` 按其 `reset_type`（regular→reset、banked→banked）映射，中文 `title`/`summary` 由人工撰写（一次性工作），`tweetUrl` 原样保留实现溯源。

派生统计（构建时计算，不入库）：`totalResets`（reset+banked 计数）、`avgIntervalDays`、`longestIntervalDays`、`daysSinceLastReset`、`lastResetAt`。

## 3. 信号抓取与推送

**抓取器（可插拔 provider）**：

```text
providers/codexResets.ts   主源：轮询 /api/resets，diff 出新事件
providers/manual.ts        兜底：录入脚本写入（见上）
（未来可加）providers/rsshub.ts、providers/telegramChannel.ts
```

- 轮询频率：每 30 分钟（GitHub Actions cron `*/30 * * * *`，免费额度内）。
- diff 规则：按 `tweet_id` 对比；新事件的 `reset_type ∈ {regular, banked}` 视为"确认重置"，触发推送；`capacity` 类仅更新数据不推送；`normal` 类不导入（页面公告流只收录与重置/容量相关的内容，控制信噪比）。
- 推送文案（企微群 markdown）：

```text
🚨 Codex 重置确认（第 N 次）
<标题> · 北京时间 <MM-DD HH:MM>
原推：<tweetUrl>
→ 去看看你的额度回来了没
```

- 推送适配器 `notify.ts`：接口为 `sendResetAlert(event)`，企微实现内部处理 webhook 地址（secret 走 GitHub Actions Secrets）；失败重试 3 次（指数退避），仍失败记录到 Actions 日志并在下次成功扫描时补发一次。
- **合规与道德约束**：仅消费其公开只读接口、保留全部原推溯源、页面标注"历史数据参考 codex-resets.com 整理"；若对方加 Robots/访问限制则立即切换人工兜底，不做绕过。

## 4. 页面设计（手机优先单页）

信息层级自上而下（沿用两个竞品已验证的信息架构，文案与视觉全部自写）：

| 区块 | 内容 | 来源能力 |
|---|---|---|
| ① 雷达状态首屏 | 状态徽章（雷达在线 / 扫描中 / 降级）；距上次重置 N 天；未来 24h 概率大数字 + 分层标签；距下次扫描倒计时（固定每 30 分钟整点，客户端计时）；CTA：进群订阅（企微群二维码）+ 查看历史 | 概率预判、扫描倒计时 |
| ② 最近重置卡 | 时间（北京时间）+ 类型徽章 + "查看原推"直链 | 公告流、溯源 |
| ③ 历史时间线 | 26 周周网格（reset/banked/capacity 三色标记，可点选查看当日事件）；统计条：累计 N 次 / 平均间隔 X 天 / 最长 Y 天 | 历史时间线 |
| ④ 公告流 | 分类筛选（全部/确认重置/重置卡/容量信号）；每条：分类徽章、相对时间、标题、一句话摘要、直链 | 公告流、溯源 |
| ⑤ 祈愿互动 | "祈愿一次"按钮，计数仅存 localStorage，文案注明娱乐性质 | 祈愿 |
| ⑥ 页脚 | 免责声明（历史规律不代表未来；与 OpenAI 无隶属；个人额度以 Codex 内显示为准）；RSS 链接；交流群入口；数据口径与更新时间 | 交流群入口、RSS |

移动端断点为基准（375–430px），桌面居中最大宽度 640px 阅读栏 + 桌面增强布局；首屏 LCP 目标 < 2.5s（静态生成，可达成）。

## 5. 概率预判算法

口径（与页面展示一致，诚实披露）：

```text
P(未来 24h 内重置) =
  count(历史相邻重置间隔中，等待天数 ≥ 当前已等待 d 的样本里，在等待第 d 天后 24h 内发生重置的次数)
  / count(历史样本中等待天数 ≥ d 的观测)
```

实现：把全部相邻确认重置（reset/banked）构成间隔序列；对每个间隔 i，"等待到第 k 天仍未重置"的观测在 k=0..i-1 各贡献一次，其中 k=i-1 的观测标记"24h 内发生"。

边界与保护：

- 样本数（分母）< 5：显示"样本不足，展示间隔分布代替"，不显示百分比。
- d ≥ 历史最长间隔：显示 ">90%（已超历史最长等待，高位）"。
- 分层标签：低 <30% / 中 30–60% / 高 >60%。
- 页面固定文案："这是趋势参考，不是 OpenAI 承诺"。

## 6. 订阅与推送流程（用户侧）

1. 用户点"进群订阅"→ 弹层展示企微群二维码 + 一句说明（"重置确认后群里 @所有人，不会发广告"）。
2. 微信/企微扫码进群 = 订阅完成，无任何表单。
3. 重置发生 → 群消息推送 → 用户点原推直链或直接打开 Codex。
4. 退订 = 退群，无留存。

不做：邮箱收集、TG（二期评估）、任何账户体系。

## 7. 错误与异常状态

| 场景 | 行为 | 页面表现 |
|---|---|---|
| 抓取源单次失败 | 保留上次数据，Actions 正常退出 | 页面照常，显示"数据更新于 <时间>" |
| 抓取源连续失败 > 24h | 停止依赖该源 | 状态徽章降级为"雷达降级 · 人工核验中"；站长收到 Actions 失败告警（GitHub 默认邮件） |
| 抓取源结构改版 | diff 校验失败即报错，不写入脏数据 | 同上，等人工适配 |
| 企微 webhook 失败 | 重试 3 次后记录，下次扫描补发一次 | 群里消息延迟，页面不受影响 |
| 概率样本不足 | 算法保护触发 | 显示间隔分布与"样本不足"说明 |
| events.json 校验失败 | CI 阻断，不允许部署 | 线上保持上一版本 |

## 8. 测试与验收

- **单元测试**：概率算法（构造已知间隔序列，断言各等待天数的概率与边界：样本不足、超最长间隔）；diff 逻辑（新增/去重/类型映射/normal 不导入）。
- **数据校验（CI）**：`events.json` schema 校验（字段完整、时间可解析、tweetUrl 格式、type 枚举）；派生统计与页面渲染数字一致性检查。
- **构建检查**：`pnpm build` 通过；关键文案存在（免责声明、无隶属声明、概率口径说明）。
- **端到端手工验收**：录入一条测试事件走完整链路（commit → 部署 → 企微推送收到），验收后删除。
- **移动端走查**：375px 宽度下无横向滚动、首屏完整呈现区块①。

## 9. 明确不做（本期）

账户体系、付费功能、Telegram/邮件推送、多语言、精选副业页、自建 X 抓取（API 成本）、浏览器 Web Push。
